# Контракт Oakle для фронтенда — 21 октября 2026

База API: `https://api.oakle.app/api/v1`. Схема: `/openapi.json`, Swagger: `/docs`.
Защищённые запросы: `Authorization: Bearer <access_token>`. Роль текущего аккаунта — поле `is_psychologist` в `GET /users/me`.

## Деньги и подписка

Новые ставки и расчёты — USD. Все поля `*_minor` содержат целое число центов: `10000` = $100.
Подписка на ИИ: **900 центов ($9) за 30 дней**. Это серверная настройка; при включении реальных покупок продукт в App Store/Google Play/RevenueCat нужно настроить отдельно. Биллинг пока работает в тестовом режиме.
Старые ставки в RUB сброшены в `null`: психолог должен указать новую ставку. Прошлые бронирования, расчёты, платежи и заработок сохраняют исходные суммы и валюты. Старые тарифные политики комиссий помечены RUB и не применяются к USD.

- `GET /billing/psychologist/me` — `hourly_net_minor`, `currency`, `test_mode`, `connected`.
- `PATCH /billing/psychologist/me` — `{"hourly_net_minor": 10000}`. Допустимо целое число 1–100000000. Это чистая часовая ставка психолога, а не полная цена для пациента.
- `POST /billing/psychologist/onboarding` — без тела. Для установки ставки не нужен. В тестовом режиме возвращает `connected: true`, `url: null`; в реальном — ссылку Stripe, ставку надо задать заранее.
- `GET /psychologists` — добавлены `avatar_url`, `hourly_net_minor`, `currency`, `hourly_price_minor`. Последнее поле — оценка полной цены 60 минут с комиссиями. Для карточек и фильтра используйте `hourly_price_minor`; при `null` показывайте «Цена уточняется».
- `GET /billing/slots/{slot_id}/quote` — окончательный расчёт выбранной длительности (`amount_minor`, `currency`). Тестовая политика без комиссий может давать одинаковые net и полную цену.

## Сброс пароля

`POST /auth/forgot-password`: `{"email":"user@example.com"}`. Успех — 202, в том числе для неизвестного адреса (защита от перечисления аккаунтов).
Письмо содержит `oakle://reset-password?token=...`. Экран обрабатывает Flutter.
`POST /auth/reset-password`: `{"token":"...","password":"..."}`. Минимум 8 символов; требований к регистру/цифрам нет.
Токен действует 1 час; после успешной смены пароля повторное использование отклоняется. Успех — 200, неверный/просроченный токен — 400 `RESET_PASSWORD_BAD_TOKEN`, короткий пароль — 400 `RESET_PASSWORD_INVALID_PASSWORD`.
Провайдер может принять письмо, но это не подтверждает доставку в почтовый ящик. В журнале backend сохраняется ID принятого Resend сообщения; для отказа/отскока/доставки нужен журнал аккаунта Resend. Пароли и токены не пересылать.

## Фото

- `POST /psychologists/me/photo` — авторизованный психолог; `multipart/form-data`, поле `file`. JPEG, PNG или WebP, до 5 MiB, до 16 млн пикселей, без анимации.
- Ответ — профиль с `avatar_url`; URL также входит в `GET /psychologists/me` и публичный каталог.
- Сервер удаляет метаданные, уменьшает изображение до 1024 px и сохраняет WebP. Файл доступен публично по возвращённому URL без JWT.
- Повторный POST заменяет фото. `DELETE /psychologists/me/photo` удаляет его и возвращает `avatar_url: null`. Старые URL перестают работать.
- Ошибки: 413 — размер; 415 — тип; 422 — изображение повреждено/анимировано/слишком большое по пикселям; 403 — неверная роль.

## Расписание

`GET /slots/my` — **психолог**, собственные ещё не закончившиеся слоты. `GET /slots/booked` — **пациент**, его подтверждённые записи. Для календаря психолога не вызывайте `/slots/booked`.
Ответы `/slots/my`, `/slots/booked`, `/slots/history` содержат прежние поля и новые:

```json
{"id":"UUID","psychologist_id":"UUID","start_at":"2026-11-01T10:00:00Z","end_at":"2026-11-01T11:00:00Z","status":"booked","patient":{"id":"UUID","first_name":"Иван","last_name":"Петров"},"latest_event":{}}
```

`latest_event` здесь сокращён; полная структура описана в OpenAPI. Имена могут быть `null`, если профиль не заполнен.
Статусы: `free`, `reserved` (ожидание оплаты), `booked`, `completed`, `missed`, `cancelled`, `removed`. В `/slots/my` отменённая запись освобождает слот (`free`); удалённые слоты исключены. У свободного слота `patient: null`.

`POST /slots/create`: `{"start_at":"2026-11-01T10:00:00+03:00","end_at":"2026-11-01T11:00:00+03:00"}`. Нужен часовой пояс (`Z` или смещение), начало в будущем, конец после начала, минимум 15 минут. Пересечения и повторы запрещены.
422 — формат/поля/пояс/конец до начала; 400 — прошлое время или слишком короткий слот; 409 — пересечение; 403 — аккаунт не психолог.
`POST /slots/{slot_id}/remove`: `{}` или `{"comment":"..."}`. Занятый слот/действующая резервация требуют сначала разрешить бронирование.

Пример 403: `{"detail":"Only psychologists can view their slots"}`.
Пример 422: массив `detail` с `loc: ["body", "start_at"]`, `type: "value_error"`, `msg: "Value error, Datetime must include timezone"`. Сохраняйте тело ошибки; одного HTTP-номера для диагностики недостаточно.

## Заявки, рекомендации и оценки

`GET /patient-assignments/incoming`, `/active`, `/finished`, а также `/my` возвращают объект `patient: {id, first_name, last_name}`. Психолог видит только свои заявки; публичного поиска пациентов нет.
Пациент получает собственное назначение через `GET /patient-assignments/my`.
`GET /ai/care-plans/{assignment_id}/patient` **не требует подписки**. Назначение должно быть активным и принадлежать пациенту, последнее событие плана — `activated`. Черновик/пауза — 409. Ответ содержит рекомендации, но не инструкции для ИИ.
Подписка по-прежнему нужна для ИИ в режиме `guided` по плану. Публикация психологом: `POST /ai/care-plans/{assignment_id}/activate` с идентификатором версии (точная схема — в OpenAPI).
`PUT /psychologists_rating/{psychologist_id}/rating`: `{"rating":5}` (необязательный `comment`). Только пациент, у которого был хотя бы один завершённый сеанс с этим психологом. Иначе 403. Повторная отправка обновляет предыдущую оценку. Одной заявки/оплаты/будущей записи для оценки недостаточно.

## Проверка фронтенда

Войти раздельно пациентом и психологом, проверить роль через `/users/me`; задать новую USD-ставку; загрузить фото; создать слот с поясом; оформить и подтвердить тестовую оплату; сверить оба календаря и имена; активировать рекомендации и открыть их пациентом без подписки. Сброс пароля проверять на устройстве с установленным приложением после фактической доставки письма.
